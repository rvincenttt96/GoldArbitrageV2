# GoldArbitrage — لایهٔ ماژولار پلتفرم‌ها

این مخزن شامل بازنویسی لایهٔ پلتفرم برای `GoldArbitrageV2` است، به‌همراه بررسی فنی پروژهٔ فعلی و
نقد سند استراتژی. فایل‌ها طوری چیده شده‌اند که مسیرشان با مخزن اصلی یکی باشد و مستقیم قابل انتقال
باشند.

## چه چیزی اینجاست

| مسیر | توضیح |
|---|---|
| `ANALYSIS.md` | بررسی فنی کامل `GoldArbitrageV2` روی کامیت `421c87d` |
| `STRATEGY_REVIEW.md` | نقد سند «تخصیص سرمایه و آربیتراژ» v0.1 |
| `docs/ADAPTER_CONTRACT.md` | نحوهٔ اضافه کردن پلتفرم، و آنچه برای طلا۳۰ و ملی‌گلد لازم است |
| `config/platforms.toml` | رجیستری پلتفرم‌ها — تنها جایی که عدد مخصوص یک پلتفرم وجود دارد |
| `core/` | مدل پلتفرم، محاسبهٔ کارمزد، رجیستری، مدل‌های داده |

```bash
python3 -m pytest tests -q
python3 -m research.compare_strategies
```

نیازمندی‌ها: پایتون ۳.۱۱ به بالا (برای `tomllib`) و `pytest` برای تست. کد اصلی وابستگی خارجی ندارد.

## ایده‌های اصلی این بازنویسی

**پلتفرم‌ها داده‌اند، نه کد.** هر عدد مخصوص یک پلتفرم — نرخ کارمزد، حداقل وزن مشمول، گام حجم،
عمر قیمت — در `platforms.toml` است. `services/opportunity_finder.py` هیچ‌جا نام پلتفرمی را چک
نمی‌کند، پس اضافه کردن پلتفرم آن فایل را تغییر نمی‌دهد.

**`enabled` از `verified` جداست.** یک پلتفرم می‌تواند قیمت بدهد ولی اجازهٔ سفارش نداشته باشد.
`PlatformRegistry.tradable()` فقط پلتفرم‌هایی را می‌دهد که هر دو را دارند. یعنی پلتفرم جدید از روز
اول داده جمع می‌کند بدون اینکه بتواند ضرر بزند.

**مقادیر میلی‌گرم صحیح‌اند و پول Decimal.** همهٔ این پلتفرم‌ها در مضارب میلی‌گرم معامله می‌کنند،
پس این واحد اتمی طبیعی است و float اصلاً وارد حسابداری نمی‌شود.

**کارمزد یک مدل است، نه یک ضرب ساده.** `FeeSpec` سه جزء دارد که با هم هر زمان‌بندی دیده‌شده را
می‌سازند: درصد ساده، درصد با حداقل وزن مشمول (کف ۰.۴ گرمی والگلد)، درصدی که به وزن طلا و با
برش به میلی‌گرم گرفته می‌شود (میلی‌گلد)، و کارمزد ثابت هر معامله.

**هر رد شدن ثبت می‌شود.** `ScanResult.rejections` علت رد هر کاندیدا را نگه می‌دارد. توزیع علت‌ها
سریع‌ترین راه تشخیص «لبه اصلاً نیست» از «لبه هست و ما به آن نمی‌رسیم» است.
